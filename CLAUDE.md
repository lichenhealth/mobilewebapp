# Lichen — PWA project guide

Lichen is a holistic-healing nonprofit + conscious-economy platform. This repo
(`lichenhealth/mobilewebapp`, package `lichen-pwa`) is the member-facing PWA.
The founder is non-technical; explain reasoning briefly and prefer small,
reviewable changes. Keep Plan Mode on for anything touching the database or auth.

For the dated, PR-by-PR story of how any of this got built — the "why" behind
a non-obvious decision — see [`docs/HISTORY.md`](docs/HISTORY.md). This file
is the current-state reference only.

## Stack & deploy
- React 18 + Vite + TypeScript. Build: `tsc -b && vite build` (it type-checks — always run before considering a change done, and fix all errors; the project builds clean).
- No package-lock; Vercel runs `npm install`. Vercel auto-deploys `main` on push.
- Backend: Supabase (project `mjqnaevertyzgjlpwynr`). Anon key is hardcoded in `src/lib/supabase.ts` (public by design; RLS protects data).
- DB schema is version-controlled in `supabase/migrations/00000000000000_init.sql` — a `pg_dump --schema-only --schema=public` baseline plus a manually-appended `auth.users` signup trigger. It's a record/backup, not auto-applied — the live schema is edited in the Supabase dashboard and this file can drift; refresh it after DB changes. Supabase CLI is linked (`supabase/config.toml`); `pg_dump` lives at `/opt/homebrew/opt/libpq/bin/pg_dump` (no Docker). `supabase db dump`/`db pull` need Docker, which isn't installed — use the direct `pg_dump` against the session pooler instead.
- Migrations can run directly: `worker/migrate.sh <file>` applies a migration via `psql` (`/opt/homebrew/opt/libpq/bin/psql`) using `SUPABASE_DB_URL` from the gitignored `worker/.env` (session-pooler URI, founder-supplied, never passes through chat). Runs as one transaction (`ON_ERROR_STOP` + `psql -1`) — a failure rolls back cleanly. Routine additive migrations can run directly and get reported after; anything destructive (dropping a column, deleting rows, rewriting existing data) needs the founder's explicit yes first.

### Domains & email
- `lichen.health` **is the app** — canonical origin (`APP_ORIGIN` in `src/lib/customDomain.ts`, `APP_URL` edge secret). `lichen.healthcare` (+www, and www.lichen.health) 308-redirects every path to the same path on `lichen.health` via `vercel.json` host-matched rules. ⚠ `/:path*` does **not** match the bare root on host rules — explicit `source: "/"` rules exist for each host; keep both when adding a new host.
- DNS: `lichen.health` stays on **Wix** nameservers (A record → Vercel). **Google-Workspace MX for `connect@lichen.health` lives there — never touch.** Transactional email still sends **from** `lichen.healthcare` (Resend MX; deliberate, invisible to members).
- Signed-out `/` on `lichen.health` serves the static Astro marketing homepage (`public/welcome/` — filesystem-first, shadows the SPA rewrite; bounces to `/home` via a localStorage auth-token check for signed-in browsers). `/get-involved`, `/founders-circle`, `/project/*` also ship static. The app itself keeps a richer in-app version of `/about`; `/blog /resources /mission /ourstory` etc. redirect to it in `App.tsx`. PWA manifest `start_url` = `/home` (installed apps skip the marketing shell).
- The old marketing site's long-form essay/reading-list import (11 founding essays + 6 reading lists, `'The Lichen essays'` / `'The Lichen bookshelf'` collections) was removed from Library 2026-08-10 — founder call, replacing it with better-curated content; full content archived to `archive/lichen_essays_and_bookshelf_backup_2026-08-10.json` before deletion. Anon users can still read public posts + published collections generally (signed-out browsing is deliberate — the growth loop); this just isn't what carries that anymore.
- To edit a static marketing page: edit the `lichenhealth/lichen-health` repo (Astro) → `npm run build` → copy the built page dirs + `_astro` into this repo's `public/` (re-inject the `welcome/index.html` auth-bounce script — it's hand-patched, not part of the Astro build) → push **both** repos. ⚠ Never `rsync --delete` the shared `public/_astro/` unless EVERY page dir ships in the same copy — hashed assets referenced by pages you didn't re-copy get deleted out from under them (it took `/welcome`'s stylesheet on 2026-08-13; restored from git). Copy `_astro` additively, or verify every `public/*/index.html`'s `/_astro/` references still resolve before pushing.

### Local verification with a test account
There's one live Supabase project (no separate staging), so "local" verification means the local Vite dev server against the real database, signed in as a dedicated, low-stakes account (`galyn+claudetest@lichen.health`, profile name "Claude Test", gifted a Community subscription) — never the founder's real one. Claude does not type a password into a login form or call `signInWithPassword` itself, even for this throwaway account — that's a hard rule, not a preference.

**Getting a session (no founder involvement needed):** `worker/mint-test-session.sh [email]` mints a fresh session server-side via Supabase's Admin Auth API (`generate_link` → `verify`) using the service-role key already in `worker/.env`, and writes it to `worker/test-session.json` (gitignored — same trust boundary as `worker/.env`). Standing Bash permission rule already covers running it, no approval prompt. Claude then injects the contents into the Browser-pane preview via `localStorage.setItem('sb-mjqnaevertyzgjlpwynr-auth-token', <contents>)` + reload.

Fallback (only if the account doesn't exist yet, or the service-role key isn't available): the founder signs into the account once in their own browser, opens devtools → Application → Local Storage, and copies the `sb-mjqnaevertyzgjlpwynr-auth-token` value into `worker/test-session.json` by hand.

**Standing protocol (founder, 2026-08-09): test before declaring UI work done.** For any UI/frontend push, sign in as the test account and actually click through the changed flow at both mobile and desktop widths in the Browser pane — not just a code read or a single screenshot — before reporting complete. Fix whatever's found, re-verify, then report. This is load-bearing, not optional polish; it's already caught real bugs (a popover-overlap and an off-screen-clipping bug) that a code read alone missed.

## Conventions
- Design tokens live in `src/styles/tokens.css` (peach accent `--peach`, blue `--blue` for admin/stewardship affordances, green `--green` for availability/free, bone canvas, Archivo body, display serif). Reuse token vars; match existing BEM-ish class names (`.onb__`, `.prof__`, `.cat__`, `.adminc__`, `.conv-row`, `.thread__`).
- Logo: `src/components/LichenMark.tsx`. Icons: `src/components/Icon.tsx` (`<Icon name=... size=... />`; top-bar section marks force 1.2px hairline strokes via `vector-effect: non-scaling-stroke` — native strokeWidths are tuned for small sizes).
- Avoid the word "spaces" in member-facing UI when you mean the ENTITIES — say organizations / communities / groups / places. Bookable **resources** are "Bookable areas & things" (founder 2026-08-11) — a stall or an arena isn't a room, and "areas" keeps "spaces" reserved for the entities. The DB column stays `resources.kind = room|thing`; only the labels changed.
- Supabase embeds: when a table has >1 FK to another, disambiguate with the explicit hint, e.g. `profiles!subscriptions_profile_id_fkey(full_name)`. SELF-referencing FKs (`spaces.parent_space_id`): do **not** embed at all — the FK-NAME hint fails outright and the COLUMN hint `spaces!parent_space_id(...)` parses but resolves to the CHILDREN direction (an array). Fetch the parent row explicitly by `parent_space_id` instead (see `spacesApi` `loadSpaceProfile`/`listSpacesByKind`).
- React hooks must ALL sit above any early return (`if (loading) return …`). A hook added below one crashes the whole app to a blank page when the data arrives ("Rendered more hooks…").
- New enum values can't be USED in the same migration that adds them — add in a separate step that's committed first.
- Only 3 columns use real Postgres enums (`account_capability`, `space_kind`, `space_member_role`). Other "enum-like" fields (care `status`, subscription `tier`/`source`, category `domain`, suggestion `status`) are actually `text` columns with CHECK constraints — to add a value, change the CHECK, not an enum type.
- RLS policies must never reference each other in a cycle (42P17 recursion) — route through a `SECURITY DEFINER` helper instead (`is_chat_member()`, `is_event_attendee()`, `owns_reminder()`, `is_space_admin()` are the existing examples; reuse the pattern for any new two-tables-reference-each-other case — including hand-rolled duplicates of an existing helper, which sit on the same latent-cycle shape even before they've actually recursed).
- Migrations pasted through the Supabase dashboard need a **named** dollar-quote tag (`$func$`, not `$$`) — the dashboard's paste can mangle a bare `$$` into `$` (42601).
- `.app-shell` must stay `overflow-x: clip`, never `hidden` — `hidden` silently kills `position: sticky` app-wide.
- `.h-scroll`'s own 12px gap beats a row's own `gap` — new horizontally-scrolling rows need a double-class selector (`.icon-row.h-scroll` etc.) to override it.
- `tokens.css`'s `--wall-gutter` is applied globally via `.scroll-view`'s `padding-inline` — a mandatory minimum side indent even when a section forgets its own padding. Full-bleed screens (chat thread, auth, maps, about, guest pages) opt out via an explicit inline `padding: 0` in `App.tsx`.
- `\u` escapes do not process inside JSX attribute strings — write the literal character in placeholder text, not the escape sequence.
- A recurring class of bug: a shared row's own back-chip/back-button styling loses an import-order specificity tie against a page-specific override. Fix with a compound selector (e.g. `.cmp__back.postp__back`), never a bare rule.
- **Scoped sections are the platform through a filter** (founder 2026-08-11) and must read as themselves even at zero. Shared parts (the `ScopeEscape` header chip was RETIRED 2026-08-13 — founder: with the way out living where the content should be, the extra button was redundant and made the UI busy): `ScopeEmpty` says "No Library content from Countryman Stables yet!" with a "Visit the Lichen Library" link (founder's wording) rather than a generic blank; and `TopBar` overlays the scoping entity's avatar on the section logo (`.top-bar__scope-badge`, the founder's preferred design solve over renaming the page) so you can see whose Library/Marketplace you're in. **A thin shelf gets the same pointer as a bare one** (founder 2026-08-13): `ScopeMore` sits UNDER the results when a scoped section has fewer than `FEW_RESULTS` (5) — "That's all the one thing Pine Valley Grange has in Marketplace so far" + a way to the whole section — never replacing what's there, unlike `ScopeEmpty` at zero. Wired in `Marketplace.tsx` + `AreaFeed.tsx` (courses/library/art/work/food/travel) + **`Events.tsx`** (which understood `?space=` all along but never got the shared pattern) and My-celium's empty web. ⚠ **Scope comes from the URL (`?space=`/`?member=`), never from acting-as** (founder 2026-08-13, asked and answered): reaching Marketplace from the icon row while wearing an org's hat is Lichen's Marketplace, deliberately — "I want to be able to participate in the lichen marketplace as countryman stables... I'm always a participant, even if i'm an org". So the ACTIONS carry the hat instead: Compose already authors as the space (`author_space_id`, with a "Posting as" banner), Current-cy already treats a space as a first-class party, and Marketplace now passes `asSpace` to `setRecommend` (⚠ read the state back with `recommendKey(...asSpace)` — the key appends `@<spaceId>`, so the bare key leaves the thumb dark). STILL PERSONAL: trust (a space has no shield, by doctrine) and messaging (`chat_members` has no space column). **Buying works through the EXCHANGE flow** (`exchanges` table, request → accept → both-say-done → Current moves; `ExchangePanel` on PostPage) — and since 2026-08-13 a space can be the BUYER (`exchanges.buyer_space_id`; `buyer_id` still records which admin acted, the truster_id pattern) and a space seller is paid INTO its treasury (completion used to credit the human who posted the space's listing — the treasury was bypassed on its own sales). The not_self rule relaxes only when a space is the real buyer ("the barn buys its admin's saddle"); a treasury purchase is admin-gated, not guardian-gated, but a minor SELLER still needs a guardian's yes. `request_exchange` gained `p_as_space` (old 4-arg dropped — one PostgREST candidate); `complete_exchange` debits/credits the PARTIES (space or person, either side), takes the same advisory-lock keyspace as `send_currentcy`, and bells a receiving treasury's admins; the frozen price now takes the FIRST number in the text (the old strip-non-numerics turned "sliding $10–$25" into **1025 Current**). `send_currentcy` also bells a space recipient's admins now. ⚠ `lichen.actingAs.<uid>` in localStorage stores a BARE space/being id, not JSON — inject accordingly when testing. `possessive()` in `src/lib/names.ts` gives "Countryman Stables'", not "Stables's".
- `loadFeed()` is the shared source for Events/Marketplace/AreaFeed/Maps/search — any filter added there needs to be **opt-in** (a flag like `{ river: true }`), not applied by default, or it silently drops posts from every other surface that calls it. Same pattern: Compose's "Skip the feed" writes `details.quiet`, honored only where `river: true` is passed.
- Consent bubbles (`ConsentBubble.tsx`) are the pattern for a setting that needs in-context explanation (presence, findability): anchored to the control it governs, an "Edit `<setting>`" door, only one visible at a time, seen-state tracked per **member** via `member_prompts` (not per device — a new phone isn't a changed mind, so don't re-prompt on it).
- The Home **Directory** (`Directory.tsx`, `/directory`) lists EVERYONE since 2026-08-14: members first (trust shield), then **Stewarded members** (non-person `profiles.kind` rows — plant/animal/place/element/collective, each with a steward who answers for it; founder 2026-08-14 chose the literal name over a prettier one, the same instinct that retired "awake"), then findable Organizations/Communities/Groups/Places (`.dir__section` headers, My-celium's ordering) — beings and spaces carry the recommend thumb, never a shield (trust is person-to-person). Search spans all of it. `MemberRow.tsx` is the one shared row for every member/space listing (Home Directory, My-celium's web, a space's Members tab) — avatar, shield-or-thumb (person→trust, space→recommend), weave mark, labeled Message door. `chatApi.ts` exports `CLAUDE_PROFILE_ID` (the single source — don't re-inline the UUID), `sortClaudeFirst()`, and `hasDirectChatWith()` (a read-only existence check on `chats.direct_key`, unlike `ensureDirectChat` which creates the row). Claude's avatar look (Si-blue circle, brain glyph) lives in `public/claude-avatar.svg`, referenced by `profiles.avatar_url` — recolor by editing that file, not in code.
- Desktop responsiveness (`@media (min-width: 1024px)`, matching the app-shell's own sidebar breakpoint) was historically added screen-by-screen, not systematically — a 2026-08-09/10 sweep applied two reusable idioms uniformly: row/tile lists go `grid-template-columns: repeat(auto-fill, minmax(Npx,1fr))` (`ListingTile.css`'s `.tile-grid` is the original), FeedCard stacks (Home/My-celium/AreaFeed's feed view/Saved) use the same idiom at `minmax(360px,1fr)`. `.prof` (shared by `Profile.tsx` and `SpaceProfile.tsx`) was hard-capped at the literal mobile width (`--app-max`, 430px) even inside the desktop column — fixed via a `SpaceProfile`-only `is-space` modifier class widening to 720px, leaving `Profile.tsx`'s genuinely-narrow settings page untouched. **Row-grid gotcha**: `MemberRow`'s icon+Message-button chrome alone eats ~172px, so a `minmax` narrower than ~400px truncates real names to a few px — checked only via computed-style JS the first time, which confirmed the CSS rule applied but not that the sparse test account's data was too thin to expose it; verify row grids against an account with real density, not just the test account.
- Doors vs. lenses (founder 2026-08-08, Marketplace; extended to Events 2026-08-10): constant tools (Search, Post, the assistant, Lichen's entrust door) are icon-only circles (`.mkt__action`/`.evt__action`, no caption) — "a circle is something you open." Type/mode filters (Marketplace's gift/trade/rent/etc., Events' Free/Trade/Paid) render as text+icon signal chips (`.mkt__lens`/`.evt__lens`, no circle, a check when on) — "text with a check is something that's on." Marketplace splits doors and lenses onto two lines — and since 2026-08-13 **Lend + Borrow share one "Lending" lens** (founder: "2 sides of the same coin", reversing the 2026-07-17 split; DB modes stay separate — Compose still authors lend vs borrow distinctly, the merge is filter-only, `CHIP_MODES.lend = ['lend','borrow']`). The lens row also uses `ScrollHintRow`'s new **`fade` mode**: the hide-until-whole rule was written for 48px icon circles, where a hidden item's leftover layout box reads as breathing room — on a text-chip row it left an 85–120px HOLE before the chevron (the founder's circled "empty space" was a hidden chip's box, via `visibility: hidden`). Fade mode never hides; a cut chip tapers under a gradient to the page canvas instead. Icon rows keep hide mode — pass `fade` only for text-chip rows; Events shares one row (only 3 modes fit fine) — same vocabulary, row count follows how many filters there are, not a fixed rule. Platform-wide tab font-weight is 300 base / ~400 active (`.evt__navtab`, `.mkt__tab`, `.conc__tab`, `.evp__tab`) — `PublicPage.css`'s `.ppage__nav-link` (About/Services/etc. template tabs on member and space profiles) and `FilterRow.css`'s active state were bolder outliers (600), fixed to match.
- Chat now has a desktop split-view: `Chat.tsx` keeps `ChatConversation` (the self-contained conversation component `ChatThread` and Concierge's care tab already reuse) inline in a `.chat__thread-pane` beside the inbox list at ≥1024px, instead of navigating to the mobile full-page `/chat/:id` (`ChatThread.tsx`) — that route/behavior is untouched below 1024px. Selection is `?open=<id>` on `/chat` (linkable/refreshable), set via `openChat()`'s desktop branch; the pane's sticky offset is `calc(var(--top-h) + var(--s-6))` to clear the topbar exactly. `ChatConversation`'s own `onBack` closes the pane back to full-width list.

## Data model (all RLS-enabled)

### Identity & profiles
- `profiles` (id→auth.users; `full_name` [kept in sync from `first_name`/`last_name` by trigger `compose_full_name` — never write `full_name` client-side], `headline`, `bio`, `email`/`phone` [**not** in the column-scoped SELECT grant — owner reads via session/`my_phone()`, others never see them directly; care team reads phone via `on_call_roster()`], `onboarded`, `is_admin`, `identity_tags` text[] [public], `home_location`/`home_lat`/`home_lng`/`home_area` [not granted — owner via `my_home()`, viewers via `mappable_members()`], `presence_visible`/`presence_lit_until`/`presence_always_present`, `timezone`, `findable` [default true], `assistant_readable` [default true], `page` jsonb [public-page template content], `contact` jsonb, `public_page` bool [default **false** for people], `handle`). Trigger creates a profile on signup. `profile_locations` (2026-08-11) — a member's **Goods & Services addresses** (label + address + optional pin), as many as needed; deliberately member-visible RLS (their point is being found), unlike home's hidden-by-default `location_shares` ladder. Both managed in Profile's "Location" accordion section (`HomeLocationSection.tsx`, content-only — Profile supplies the CollapsibleSection chrome). Per-address `show_on_maps`/`show_on_profile` booleans (default true, instant-apply checkboxes under each row): pinned addresses ride Maps' **Places** layer (`loadBizLocationPins()` → `biz:` markers in `MapView.tsx`, popup → View member), and show-on-profile addresses render as extra Practical rows on the member's public page (`loadProfileBizLocations()` → `PublicPage`'s `bizLocations` prop via `MemberProfile.tsx` — also widens `hasContact`, so an address alone summons the Contact tab).
- `can_see_profile()` gates profile reads (replaced a blanket `USING (true)`): visible if `findable=true`, OR you share a space/chat/care-team/web edge with them, OR you're reading one of their public posts (a feed has to be able to name its author). Because that last arm can't be replicated in a plain client query, Directory/people-search/type-aheads additionally filter `findable` themselves.
- `profile_capabilities` (service_provider / goods_provider). `financial_positions` (pk profile_id; income_band CHECK, household_size, circumstances; RLS = owner-all + active care-team SELECT-only — never a score, never shown to anyone else).
- `categories` (3 domains: good / service / place; text slug id, name, sort, `section` healing|everyday) + `profile_categories`. Member-suggested via `category_suggestions` + admin RPCs `approve_category_suggestion()` / `reject_category_suggestion()`.

### Spaces & membership
- `spaces` (kind enum organization|community|group|place; `created_by`; `parent_space_id` — groups nest under communities/orgs, nullable = standalone; `handle` — routes `/:handle`; `lat`/`lng`; `contact`/`page` jsonb; `public_page` [default true for org/place, false for community/group — enforced by the `set_space_public_page_default()` BEFORE INSERT trigger, since a column DEFAULT can't reference another column of the same row; the page-BUILDER itself, `PageTabsEditor`, is unconditional for all four kinds, only this default differs]; `cohort_of` [→ collections, when this space is a course cohort], `term`; `findable`/`assistant_readable`/`content_ai_default`/`content_download_default` [default true, mirror the same-named `profiles` columns — a space's own Privacy section, `SpaceProfile.tsx` backstage]) + `space_members` (role enum super_admin|admin|member; `duties` text[] — null = full admin, v1 keys `library`/`courses`/`members`). Creator becomes super_admin via `handle_new_space` trigger; one super_admin per space. `set_member_role()` is the only door for granting/scoping roles (super-admin-only).
- Membership is **request + approval**: `space_membership_requests` (`initiated_by=self` → admin approves via `approve_join_request()`; `initiated_by=admin` → invitee accepts via `accept_space_invite()`, which requires the initiator be an admin — a bare member suggestion can't self-accept). A third INSERT-policy arm lets any member file a *suggestion* for someone else; admins turn it into a real invite via `endorse_member_suggestion()`.
- Nesting is **consensual**: `space_nesting_requests` (a group is created standalone immediately; parent admins approve via `approve_group_nesting()` or release later via `eject_group()`; trigger `enforce_parent_consent` blocks non-consensual parent writes).
- `space_section_shares` (pk space+post+area; pending/approved/declined) — a space's Courses/Library sections show only space-authored posts plus duty-approved member shares; `decide_section_share()` RPC.

### Chat
- `chats` (kind organization|community|group|place|care_team|direct|event|help) + `chat_members` (synced from `space_members` via trigger; `last_read_at` = per-member read cursor) + `chat_messages` (realtime enabled). RLS goes through the `is_chat_member()` helper to avoid recursion. `ensure_direct_chat()` for 1:1 DMs. `mark_chat_read(chat)` bumps the cursor and clears that chat's notifications. `chat_unread_counts()` RPC powers inbox pills.
- `profiles.assistant_readable` gates whether **other members'** assistants can read your message *content* in a cross-chat briefing — your own assistant always sees your messages; the fact you wrote (not the content) still counts for someone whose flag is off.

### Care
- `care_team_members` (patient_id, caregiver_id, status pending|active, initiated_by — either party can initiate via `offerCareFor()`, the other approves; activation creates/joins the care-team chat). `care_invitations` (email invites for non-members; `claim_care_invitations()` on signup). `care_posts` (WOW 0–100 scores + Kindnesses-of-Care recurring board). **The WOW kicks off with a SELF-evaluation** (founder 2026-08-14): all six dimensions (Mental/Physical/Social/Spiritual/Economic/Environmental — `WOW_DIMENSIONS`, they predate this) in the member's own words with an optional self-score each; every answered dimension becomes a wow post AUTHORED BY THE PATIENT (`SelfAudit` in Concierge.tsx, shown on your own board until you've authored something; `/concierge/wow/edit` is the self-composer route — no `:patientId` = your own board). RLS gained the matching self-arm (insert/update/delete `author_id = auth.uid() AND patient_id = auth.uid()` alongside the caregiver arms) and `care_posts_kind_shape` no longer requires a score on wow posts (words-only entries are real). **Scores are a NOW-reading, not a GPA** (founder asked "running average?" — answered no): each dimension averages entries from the last 90 days (`WOW_WINDOW_DAYS`, self + care team weighted equally), a quiet dimension carries its latest older entry forward, overall = avg of the six currents; history stays in the feed for a future trend view. The Financial position card stays separate/structured; its own not-shared state now says the trade-off out loud (no rebalancing economy, no care-team help with that piece — honest copy, deliberately not an enforced gate yet). **The self-driving window** (founder 2026-08-14, same conversation: "allow humans to trust you automating it... kinda like self driving cars"): a member may hand the window to Claude — `care_settings` (patient-owned row, care-team SELECT via `is_on_care_team`; `wow_window_days` 14–120 / `wow_window_auto` / `wow_window_reason` / `wow_window_set_at`) + the `wow-window` edge function (caller is ALWAYS the patient, no target param; requires `wow_window_auto` already on; throttled server-side to one model call per 7 days, so no daily-cap bookkeeping; reads only dates/dims/scores, never the words; clamps Claude's pick and stores it WITH its one-sentence reason — a tuned window with no reason would be a hidden model again). UI is the `.wowwin` line under the radar chips (own board only): "Scores read your last 60 days · Let Claude tune it" ⇄ "Claude tunes your window as you evolve — currently N days. '<reason>' · Take the wheel back"; a stale window (>7d) re-tunes quietly on arrival. Caregivers render the client's radar through the same window (they read `care_settings`), keeping every viewer's numbers identical. ⚠ max_tokens matters: 300 silently truncated the reply into the fallback; it's 600 now. `on_call_roster(patient)` (SECURITY DEFINER — gated to the patient or a fellow active caregiver).

### Membership & subscriptions
- `subscriptions` (tier community|concierge, source gift|stripe, status active|past_due|canceled, `current_period_end` — gifts reuse it as their end date). Admin RPCs `gift_subscription(email, tier, months?)` / `revoke_subscription()` (deletes the row — does NOT touch Stripe billing). `membership_gifts` — pending gifts keyed to an invitee's email, claimed via `claim_gifts_for_email(user, email)` (the shared loop; `claim_membership_gift()` is a thin JWT-email wrapper, and `claim_invite()` calls it with the TOKEN's invitee_email so a gift lands even when someone signs up under a different address). `grant_growth_gift()` — every member gets one 3-month Concierge gift automatically (self, on-conflict-do-nothing so it's truly once); called from the App gate right before it would redirect to `/membership`.
- Admin membership toolbox (`/admin/supporters`, 2026-08-11): "Find a member" searches ALL members via `admin_search_members()` (SECURITY DEFINER — emails aren't in the column grants) and gives per-member actions: gift/upgrade/extend/revoke, and for Stripe members **Override with a gift** / **Revoke & cancel** — both route through the `admin-cancel-stripe` edge function (admin-JWT-gated, cancels Stripe immediately). `stripe-webhook` treats an active `source='gift'` row with null stripe ids as a deliberate admin override and won't clobber it with renewal/deleted events.
- Membership gate (`App.tsx`, session-cached ref): signed-in + onboarded + non-admin needs an active/past_due subscription or a live gift, else → `/membership`. `GATE_EXEMPT` = auth flows + `/membership` + `/help` + `/donate` + `/privacy` + `/terms` + `/about`. Admins always bypass. Signed-out visitors can still browse public content.

### Presence
- **Three states: PRESENT, AVAILABLE, and ELSEWHERE** (founder 2026-08-13/14). "Elsewhere" is the NAME of the neither-present-nor-available state (founder 2026-08-14) — use it in docs, code, and any future UI that must label the state itself (member rows, directory groupings); Home's greeting renders an all-elsewhere network as "out living" (see below), not the word "elsewhere". The word "awake" is retired — "it sounds a bit off, like either they're enlightened, or they're sleeping when not on Lichen." The four RPCs are `network_present_count`/`_list` and `space_present_count`/`_list` (old `*_awake_*` names dropped, not aliased).
  - **PRESENT** = `(presence_always_present or presence_lit_until > now()) and last_seen_at > now() - interval '5 minutes'` — here NOW, not here today. Both arms take the freshness guard, so a hand-lit candle no longer outlives the session that lit it. `profiles.presence_visible` and the old "around" dot are retired (column stays, unread): nothing shows that someone is merely online. The candle **defaults on** and the existing cohort was backfilled, so present means *online and hasn't snuffed* — honest only because `PresencePrompt` teaches the gesture on first open, once a day, for the **first 3 visits** (`member_prompts.times_seen`), then goes quiet forever.
  - ⚠ **The window and the heartbeat are a pair.** `AuthProvider.tsx` beats `last_seen_at` every **2 minutes and only while the tab is visible** (plus immediately on `visibilitychange` back to visible). 5 minutes is 2.5× the beat — shorten the window below ~2× the beat, or slow the beat without lengthening the window, and presence STROBES for someone sitting right there. Change them together. Visibility-gating is what makes it true rather than merely fast: a backgrounded tab or a pocketed phone stops beating, so it stops claiming you're open to being interrupted.
  - ⚠ **The Browser-pane preview reports `document.visibilityState === 'hidden'`**, so the heartbeat never fires there and presence always reads 0 while testing. Not a bug — fake it with `Object.defineProperty(document,'visibilityState',{value:'visible',configurable:true})` + `dispatchEvent(new Event('visibilitychange'))`, which is how the beat→204→count round trip was verified.
  - **AVAILABLE** = inside your published **social** hours, minus what's booked. Asks nothing of you at the time — set your hours, close the app ("I just want people to be offline as much as possible, but be able to signal when they're available"). `availability_windows.kind` now carries three: `available` (work, bookable), **`social`** (what Home counts), `on_call` (the care rota, not subtracted by bookings). All edited in **Calendar settings**, which already had the weekly-hours editor — never add a second one in Profile. Matched in the MEMBER's own timezone (`profiles.timezone`), gated by `calendar_level()` so availability is never public, and **disjoint from present** (present wins; nobody is counted twice). The booked-subtraction happens CLIENT-side in `presenceApi.availableList()` because recurrence lives in exactly one engine (`src/lib/recurrence.ts`) and a SQL expander would fork it — the SQL returns in-hours candidates plus their local date/minute, the client drops anyone busy via `free_busy()` + `occursOn()`. Revisit at thousands of members.
  - **Nobody is available or bookable by default** (founder 2026-08-14): `availability_windows` starts empty and no-hours means NOT available — unknown is never yes, the platform-wide rule. Find-a-time ("Everyone free?") counts only members with real signal (declared work/social hours, or busy time their `calendar_shares` let the viewer see; on-call never counts as meeting availability), shades 7am–9pm only, and a legend names the coverage ("Going on N of M members' shared hours…"; zero signal = no shading, just the truth). BookSession with `windows.length === 0` says "«name» hasn't set up their availability hours yet" + **Let them know**: a `notify('booking_nudge', …)` bell (client-callable, link → `/calendar/settings`) plus a prefilled DM via `?draft=` on the chat thread (`ChatConversation` prefill, member sends it themselves — the platform has no voice in chat). Demand becomes the setup moment, the candle pattern again.
  - Home reads "*N are present and M are available*"; at zero it reads "**Your network is out living.**" (founder 2026-08-13: nobody here is a GOOD sign — "a utility for healthy, real engagement in the world, not a social network that's addictive"; "resting" implied being here was the natural state, the same trap as "awake"); work hours never reach that line (Home is for connection, not commerce). Acting as a space, the count is that space's own members, present only — a space doesn't publish hours, its members do. Neither tier gates messaging: they set expectations. ### Snapshot vs Sync (founder 2026-08-11)
